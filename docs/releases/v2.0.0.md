# v2.0.0

**Status:** Pending release. This page will be finalized when v2.0.0 is tagged.
**Expected:** See `[Unreleased]` in [`CHANGELOG.md`](https://github.com/pssah4/digital-innovation-agents/blob/main/CHANGELOG.md)
for the current work-in-progress.

## Summary

v2.0.0 is a major release that brings Digital Innovation Agents to
**multi-platform plugin distribution** with **significantly upgraded
skill content**. The V-Model workflow is the same; the skills that
implement it are better.

## Highlights

### Multi-platform plugin distribution

The skills are now installable on 6 platforms through their native
plugin mechanisms, plus GitHub Copilot Chat via `.github/` and a
legacy shell installer:

- **Claude Code** -- `/plugin install digital-innovation-agents@pssah4-skills`
- **Cursor** -- `/add-plugin digital-innovation-agents`
- **GitHub Copilot CLI** -- `copilot plugin install digital-innovation-agents@pssah4-skills`
- **Codex** -- symlink-based native skill discovery
- **OpenCode** -- `opencode.json` plugin entry
- **Gemini CLI** -- `gemini extensions install https://github.com/pssah4/digital-innovation-agents`
- **GitHub Copilot Chat (VS Code)** -- copy `.github/` to your project
- **Legacy shell script** -- `./scripts/install-skills.sh`

See [Installation](../tutorials/installation).

### Upgraded `/coding` skill

Phase 1 (Context load), Phase 2 (Critical review), and Phase 4 (Final
sync) are preserved from v1 as the core differentiators. Phase 3
(Implementation) is enhanced with 5 new sub-phases that brief the
Default agent:

- **Phase 3a:** Task-breakdown guidelines (bite-size tasks, no placeholders)
- **Phase 3b:** Optional TDD mode (opt-in)
- **Phase 3c:** 4-phase debugging protocol with "architecture alarm"
  after 3+ failed fixes
- **Phase 4a:** Verification gate -- no completion claims without fresh evidence
- **Phase 4b:** Regression test cycle for bug fixes (Red-Green-Red verify)

See the [Coding guide](../guides/coding) and
[Verification Gates concept](../concepts/verification-gates).

### `/testing` role alongside TDD

When `/coding` ran in TDD mode, `/testing` focuses on integration
tests, unit-test gaps, and coverage checks. Without TDD mode, it falls
back to its original unit-test role. See the [Testing guide](../guides/testing).

### Phase 7 Release Closure

`/v-model-workflow` now has a final phase that closes the cycle:
artifact synchronization across all phases, release notes generation,
CHANGELOG update, backlog cleanup, and a closing report. See the
[V-Model workflow guide](../guides/v-model-workflow).

### Mandatory Handoff Rituals

Every phase skill now ends with a mandatory 3-part Handoff Ritual:
artifact report, handoff context appended to `30_handoffs.md`,
explicit transition question. See
[Handoff Rituals concept](../concepts/handoff-rituals).

### New file conventions

- `_devprocess/context/20_bugs.md` -- FIX-NN bug log, written by
  `/coding` Phase 3c (Debugging Protocol)
- `_devprocess/context/30_handoffs.md` -- append-only phase handoffs
  log, written by each phase skill

### VitePress documentation site

This site you are reading right now. Tutorials, Guides, Reference,
Concepts, and Releases, all hosted on GitHub Pages and built with
VitePress + Mermaid.

### Full English translation

All skill files are now in English for portability. The agent
**automatically switches to the user's language in dialog** -- skill
instructions stay English internally, user-facing messages adapt.

## Breaking changes

- **Directory rename**: skills moved from `claude-code-skills/` to
  `skills/` to match the Claude Code plugin convention. The v1.0.0 tag
  retains the old layout.
- **Script path**: `install-skills.sh` moved from
  `claude-code-skills/install-skills.sh` to `scripts/install-skills.sh`.
  The script's `--version` flag auto-detects v1 vs v2 directory layouts.
- **Feature lifecycle**: Phase 4 `/coding` now requires a verification
  gate before completion claims. This is stricter than v1's ad-hoc
  completion style.

## Migration from v1

- The skills are **backwards compatible in intent**: the V-Model phases
  are the same, the artifacts are in the same locations, the workflow
  produces the same output types.
- Projects that used v1 can upgrade to v2 by reinstalling via the
  plugin marketplace or the updated shell script. No project-level
  migration is required.
- v1.0.0 remains installable via
  `./scripts/install-skills.sh --version v1.0.0`. See [v1.0.0 release notes](./v1.0.0).
